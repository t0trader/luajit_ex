本页汇总本分支从 OpenResty LuaJIT（openresty/luajit2）移植的全部特性、 相对参考实现的修正，以及未移植项及原因。 验证平台：WSL2（GCC x64）与 Windows（MSVC x64），两平台均构建通过并跑完回归。 各特性的详细使用说明见 Extensions。

2. 优化与默认参数

2.1 JIT 默认参数

参数 旧值 新值
maxtrace10008000
maxrecord400016000
minstitch03
maxmcode2048 KB40960 KB

其余参数（maxirconst、maxside、maxsnap、hotloop、 hotexit、tryside、instunroll、loopunroll、 callunroll、recunroll、sizemcode）与参考实现一致。 行为验证（同一二进制内用 jit.opt.start() 强制回旧值对照）：

  • maxtrace：1200 个常驻 trace 时默认存活 1203 个；强制 1000 时触发上限并 flush，仅存活 204 个。
  • maxrecord：5000 条语句的超长循环体在默认值下成功编译；强制 4000 时报 trace too long。
  • maxmcode：600 个大 trace 默认存活 608 个；强制 2048 KB 时出现 failed to allocate mcode memory 并 [TRACE flush]，仅存活 192 个。

2.2 SSE4.2（CRC32）字符串哈希

  • 新增 src/lj_str_hash.c：移植 hash_sparse_sse42（len<4 与 ≥128 常量时间采样， [4,16) 两条 CRC32，[16,128) 16 字节步进 CRC32）与 hash_dense_sse42（随机 16 块 CRC32 重哈希）。
  • src/lj_str.c：原 ARX 实现改名 _def，启用时改为函数指针，并在 lj_str_init（首个字符串驻留之前）用 lj_vm_cpuid 检测 SSE4.2 后切换。
  • src/lj_arch.h：x64 + GCC/Clang 默认启用，-DLUAJIT_DISABLE_SSE42_STRHASH 可关闭。
  • src/Makefile：lj_str_hash.o 入列，新增按文件 F_CFLAGS 机制，x64 使用 -msse4.2。

实测（同机交替 4 轮）：查找（len 12/48/200/600）与纯 ARX 持平； 新建字符串 len48 约快 30–35%，len200 约快 25–30%，len12 持平； 敌意碰撞串（同首/中/尾字节、len200、1 万条）结果正确且耗时与 ARX 持平。

2.3 upvalue 上限

src/lj_def.h 的 LJ_MAX_UPVAL 由 60 提升到 120 （LJ_MAX_VSTACK、解析器 uvmap/uvtmp、checklimit 自动适配； JIT 侧编码上限为 127，120 在安全范围内）。验证：120 个 upvalue 正常编译运行， 121 个报 more than 120 upvalues，debug.getupvalue(120)、 string.dump/loadstring 往返、嵌套闭包、高索引 upvalue 的 JIT 录制、 -bL 列表显示 ; u120、-b 字节码保存/加载均正常。

3. 字节码工具链

  • -bL（列表 + 行号）：src/lib_jit.c 的 jit.util.funcbc(func, pc, lineinfo) 新增第 3 参数与第 3 个返回值； src/jit/bc.lua 增加行号列；src/jit/bcsave.lua 新增 -L 选项。
  • 常量表：-bl 与 -bL 均输出负索引 KGC （字符串/原型/函数/表）与正索引 KN（数值常量）。
  • bcnames 定宽错位修复：jit/vmdef.lua 的 bcnames 按 6 字符定宽打包， 而 Lua 5.5 兼容工作新增的 ERRNNIL、VARGIDX 为 7 字符， 导致第 73 个操作码起全部右移。已重命名为 ERRNIL、VARGIX （涉及 src/lj_bc.h、src/lj_parse.c、src/lj_record.c、 src/lj_meta.c 及 7 个 vm_*.dasc）。
  • -jdump=b 源位置：每条录制字节码后追加 (file:line)（src/jit/dump.lua）。
  • -b -a 新架构：map_arch 增加 ppc64、ppc64le、 s390x，可生成对应 ELF 目标文件（Windows 下需配合 -o linux）。

4. JIT 调试设施

4.1 saved_jit_base

src/lj_obj.h 的 global_State 新增 MRef saved_jit_base； src/lj_err.c 的 lj_err_throw 在清除 g->jit_base 前先保存， 使抛错状态下调试器仍能重建 JIT 帧的 Lua 调用栈（与参考实现一致，LuaJIT 自身只写不读）。

4.2 trace 事件日志（LUA_USE_TRACE_LOGS）

  • src/lj_debug.h / src/lj_debug.c：64 条事件的内存环形缓冲， 记录 trace 进入/退出/开始录制（traceno、exitno、是否直接退出、pc、线程、当前函数）。
  • src/lj_trace.c：trace_start 记录 START；lj_trace_exit 记录 NORMAL EXIT。
  • src/vm_x64.dasc：->vm_exit_interp 记录 DIRECT EXIT； BC_JLOOP 记录 ENTRY（Win64 按参考实现跳过）。 src/vm_x86.dasc 同样两处，用 |.if X64 保护。
  • 启用方式（VM 钩子的 #ifdef 由 buildvm 展开，因此 host 编译也需该宏）： 
    make XCFLAGS=-DLUA_USE_TRACE_LOGS HOST_XCFLAGS='-I. -DLUA_USE_TRACE_LOGS'

6. 验证方法

  • 构建：WSL make -j4；Windows Launch-VsDevShell + msvcbuild.bat。
  • 回归（d:\srccode\vibecode\ljtest\regress.sh）：regress.lua 在 JIT 与 -joff 下均 ALL OK；-jv 连续 10 次运行 0 失败； 基准（named_write / named_dyn / named_dynidx）与改前持平。
  • 对照验证：-bL / -bl / -jdump=b 与参考实现逐行一致； thread.exdata、命名变参数值与参考实现、Lua 5.5.1 一致； C API（lua_resetthread、lua_set/getexdata*）用独立 C 程序链接 libluajit.a 验证。

7. 未移植项及原因

项目 原因
s390x、PPC64（OPD/ELFv2/PPC32ON64）架构后端 需要新增 VM 后端（vm_s390x.dasc、dasm_s390x.h 等）及完整移植， 属架构移植范畴；仅在 -b -a 的对象格式表中支持其目标文件输出
JIT_F_SSE4_2 内部标志、src/lj_init.c 静态构造函数 参考实现用构造函数选择哈希；本实现在 lj_str_init 中直接 CPUID 检测，无需该标志
jit/bc.lua 中被注释掉的 else 分支 纯注释，无功能差异
CCDEBUG= -g 默认开启、安装符号链接等发行细节 与本分支的构建约定无关
